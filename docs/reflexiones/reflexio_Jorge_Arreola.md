# Reflexión individual

**Jorge Antonio Arreola Cantú**

Durante el desarrollo de este proyecto pude ampliar mis conocimientos sobre la integración de aplicaciones y comprender mejor lo que implica construir un sistema de software de gran tamaño. La plataforma de microhubs representó un reto debido a la cantidad de funcionalidades, tecnologías y componentes que necesitaban trabajar en conjunto. A diferencia de otros proyectos universitarios, en los que normalmente se desarrolla una aplicación con funciones específicas, en este caso fue necesario considerar aspectos operativos, administrativos, logísticos y financieros dentro de una misma plataforma.

Una de las decisiones técnicas que considero más importantes fue utilizar una arquitectura de 26 microservicios. Aunque desarrollar una aplicación monolítica podría haber sido más sencillo al principio, dividir el sistema permite organizar mejor las responsabilidades de cada componente, facilitar su mantenimiento y localizar errores de manera más específica. Sin embargo, también comprendí que utilizar microservicios no significa necesariamente que todo sea más sencillo, ya que aparecen nuevos retos relacionados con la comunicación, la disponibilidad de los servicios y la consistencia de la información.

Otro aspecto que me pareció interesante fue la integración de las tres aplicaciones principales del proyecto. El sistema web desarrollado con Python, la aplicación móvil con Kotlin y la aplicación de escritorio con C# demuestran que es posible utilizar diferentes lenguajes de programación dentro de una misma solución. Cada aplicación tiene un propósito diferente y está diseñada para determinadas necesidades de los usuarios. Esto me permitió comprender que no es necesario utilizar una sola tecnología para desarrollar un sistema completo, siempre y cuando exista una comunicación correctamente definida entre sus componentes.

El uso de JSON y XML también me ayudó a entender la importancia de establecer contratos de comunicación. Antes consideraba que enviar y recibir información mediante una API era un proceso relativamente sencillo, pero cuando existen múltiples aplicaciones y servicios es necesario establecer reglas para evitar problemas de compatibilidad. Una modificación en la estructura de una respuesta puede afectar varias funcionalidades. Por esta razón, considero que la documentación de las API y la validación de los datos mediante esquemas XSD son elementos importantes para mantener una integración ordenada.

En cuanto al almacenamiento de información, utilizar PostgreSQL, MongoDB y Redis dentro del mismo proyecto me permitió conocer mejor las ventajas de cada tecnología. PostgreSQL resulta adecuado para almacenar información estructurada y mantener la integridad de las operaciones, mientras que MongoDB facilita el manejo de documentos, eventos y registros de seguimiento. Por otro lado, Redis permite acceder rápidamente a determinada información y administrar las sesiones de los usuarios. Esto me hizo comprender que la selección de una base de datos debe realizarse de acuerdo con las necesidades del sistema y no únicamente por preferencia personal.

Uno de los problemas técnicos que más me llamó la atención fue el rendimiento de las consultas cuando se trabaja con grandes cantidades de información. Un ejemplo fue la sincronización de demanda, que llegó a tardar aproximadamente 37 segundos antes de las optimizaciones. Mediante el uso de índices, almacenamiento en caché y la reducción de operaciones repetitivas, ese tiempo se redujo considerablemente. Este resultado me permitió apreciar la diferencia entre desarrollar una funcionalidad que simplemente cumple con su objetivo y desarrollar una solución que también utiliza eficientemente los recursos disponibles.

Las pruebas de carga fueron otro elemento importante para comprender las limitaciones de la plataforma. Aunque el sistema podía atender a 100 usuarios simultáneos sin presentar errores durante las pruebas documentadas, al aumentar la cantidad de usuarios comenzaron a aparecer problemas de rendimiento. Considero que identificar estos límites es importante porque permite tomar decisiones sobre posibles mejoras antes de implementar el sistema en un entorno con una mayor demanda. También comprendí que aumentar los recursos de infraestructura no siempre es la primera solución, ya que optimizar el código y las consultas puede producir mejoras significativas.

Respecto a la seguridad, aprendí la importancia de proteger tanto la información de los usuarios como la comunicación entre aplicaciones. La utilización de tokens JWT, permisos según el perfil del usuario, conexiones HTTPS y mecanismos de validación permite establecer diferentes niveles de protección. También considero acertado que el sistema rechace determinadas operaciones cuando no puede verificar correctamente una sesión. En un entorno profesional, permitir que una aplicación continúe funcionando sin comprobar sus mecanismos de seguridad podría generar consecuencias más graves que una interrupción temporal del servicio.

Los algoritmos utilizados también me parecieron relevantes, especialmente la optimización de rutas y la simulación Monte Carlo. Estas funcionalidades demuestran que el desarrollo de software puede combinarse con conocimientos matemáticos para resolver problemas relacionados con la operación de un negocio. La plataforma no solamente permite administrar pedidos e inventarios, sino que también proporciona información para evaluar costos, capacidad y rentabilidad. Esto me ayudó a comprender que un sistema puede aportar valor incluso cuando sus resultados indican que una propuesta de negocio necesita cambios para ser viable.

En cuanto al trabajo en equipo, considero que uno de los mayores aprendizajes fue comprender la importancia de la coordinación entre los integrantes. Cuando cada persona trabaja en diferentes componentes, es necesario mantener una comunicación constante para evitar incompatibilidades, duplicación de tareas o confusiones sobre las responsabilidades. GitHub fue una herramienta importante para centralizar el proyecto, compartir avances y mantener un registro de los cambios. También comprendí que documentar correctamente el trabajo facilita que los demás integrantes puedan entender y continuar desarrollando una funcionalidad.

Si volviera a realizar un proyecto de estas dimensiones, buscaría establecer desde el principio una distribución más clara de las responsabilidades, realizar pruebas de integración con mayor frecuencia y dedicar más tiempo a revisar los posibles problemas de rendimiento. También consideraría implementar una mayor independencia entre las bases de datos de los microservicios y mejorar la automatización de las pruebas y los despliegues. Aunque estas decisiones podrían aumentar la complejidad inicial, considero que facilitarían el mantenimiento y la evolución del sistema a largo plazo.

Finalmente, este proyecto me permitió tener una perspectiva más amplia sobre lo que significa desarrollar software en un entorno profesional. Me llevo como aprendizaje que programar es solamente una parte del proceso, ya que también es necesario considerar la arquitectura, la seguridad, el rendimiento, la documentación y la experiencia de los usuarios. Además, comprendí que la capacidad de adaptarse a nuevas tecnologías, resolver problemas y colaborar con otras personas es tan importante como los conocimientos técnicos. Considero que esta experiencia será útil para mi futuro profesional y para enfrentar proyectos de mayor complejidad con una mejor preparación.
